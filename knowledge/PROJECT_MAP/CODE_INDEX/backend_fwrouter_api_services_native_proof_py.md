# `fwrouter_api.services.native_proof`

## Purpose

`collect_native_proof(scope="ui", expected_backend_manifest_sha256=..., expected_xray_image_digest=..., expected_mihomo_image_digest=...)` produces a bounded, read-only proof for the managed Xray, Mihomo, and Core state consumed by the UI. Its source identity is the exact installed backend content manifest rooted at the resolved `__file__` of the executing module; `FWROUTER_BACKEND_ROOT` cannot redirect attestation, and the module does not infer a Git commit from installed files. Runtime pins are the immutable local Docker image configuration IDs (`docker inspect .Image`), not registry manifest digests (`RepoDigest`); missing pins return `INCOMPLETE`, and observed IDs must match. Configured image references and reported runtime versions are checked separately.

## Read and consistency contract

- Requires an exact expected backend manifest SHA-256 and reports `STALE` when installed content differs.
- Opens SQLite with `mode=ro`, `query_only=ON`, and explicit read transactions. It captures schema/integrity/foreign-key state, generation and monotonic selection/Core revisions, latest apply ownership, active jobs, and the generation checkpoint before and after native readbacks.
- Holds `xray_writer_read_guard()` across the proof. The guard takes a nonblocking shared flock on the existing Xray writer lock only; it never creates or changes a lock file. Missing lock or active writer yields `INCOMPLETE`.
- Reads active/mounted Xray configuration and HandlerService users, and compares loaded identities plus durable binding/mode projections against the active config. Mihomo compares the complete generated semantic config, actual native top-level rules and owned selector memberships, and the effective native target against the durable Core selection in auto/fixed mode. Core compares the applied manifest, owner-recorded canonical live nft table semantics (all owned chains/rules/sets/named counter declarations; only volatile counter values, handles, and elements in the two named runtime DNS timeout sets are normalized), required chains/mode, and a SHA-256 over the complete ordered IPv4/IPv6 `ip rule` state and table-100 routes. It requests numeric table output from `iproute2` (`-N`) so local table aliases cannot change policy comparisons. IPv4 and active-IPv6 local default-route readback accepts `local` or numeric `RTN_LOCAL` `2`; unicast never satisfies the check. IPv6-disabled mode is accepted only with exact matching of the `ip link` name/index inventory and sysctl entries, `disable_ipv6=1` for all/default/lo/every interface, and empty all-interface IPv6 address and all-table route readbacks. Those bounded facts are included in hashed Core semantics and the closing owner fence; active IPv6 still requires both mark rules and its local default route. In disabled mode, the reported `-6_local_default_route` remains false when no route exists, with separate `-6_disabled_mode_proven` and `-6_policy_enforced` checks. The Core applied-manifest bytes are read and streamed-hashed under a dedicated 64 MiB limit, with the parsed read bound to the exact bytes and closing hash required to match; this accommodates the observed ~24 MB manifest without widening other artifact bounds. Raw IP rows/sysctl facts stay in process memory; only the digest is persisted or returned. The collector rechecks relevant runtime incarnations and configuration identities.
- The three IPv6 `ip -j` observations use a selector-drained subprocess with a 4 MiB stdout cap, 64 KiB stderr cap, and three-second command deadline. Overflow terminates and reaps the process; nonzero exit, timeout, invalid JSON, or process denial fails closed. Retained capture bytes are bounded; the contract does not claim bounds over kernel pipe buffers or the child process's internal memory.
- Mihomo's generated YAML uses the established stable, no-follow reader and 32 MiB YAML bound. The semantic parser and SHA-256 consume the exact same captured text bytes, and a closing stable-file hash must match; the proof does not depend on alternate adapter-supplied `_config_text()` or the generic 16 MiB native-artifact reader for this config.
- The Core manifest comparison intentionally excludes `active_auto_server_id`: the selection owner may update it without a Core manifest republish. Its revision is fenced, and Mihomo's actual selector target is separately resolved against the durable logical server ID.
- Generation proof digest and revision must exactly match the verified inventory. The generation owner may persist an additional native-proof tuple only after successful capture; legacy markers without that tuple remain readable but produce `INCOMPLETE` until a normal qualified owner promotion captures one.
- Returns only structured status and redacted identities. Raw configurations, credentials, UUIDs, selector names, job IDs, and durable source fingerprints are never included.
- `PASS` requires supported scope, exact source identity and runtime image pins, stable fences, healthy database integrity, no active jobs, a verified subscription generation and matching owner receipt, and successful native readbacks. Runtime unavailability or missing owner evidence is `INCOMPLETE`; contradictory readback is `FAIL`; changed fences are `STALE`. Public results expose only redacted hashes/counts, a proof schema version, executed-check names, and stable reason codes; unknown exception text is not returned.
- Mihomo owner receipt matching supports ordinary full/`None`, proof-only ten-field, and fixed-generation eight-field routing profiles. It computes shared tables/files/source once, requires one exact complete fingerprint match, binds the proof-only profile to the direct owner plus read-only database routing/selection snapshot, carries the matched receipt through UDP/native reads, then closes its state/config/runtime fence before returning.

## Operational boundary

This collector is observation only. It does not enter admission/staging/reconcile/apply paths, write probe caches, create temporary configs or Docker state directories, or alter SQLite/checkpoints/configs. Nested application projections run under the context-local `readonly_db_session_scope`; attempted writes fail through SQLite `query_only` and do not fall back to writable sessions. In WAL mode SQLite may update shared-memory reader bookkeeping, so the contract protects durable database/config state rather than promising bit-for-bit unchanged WAL/SHM files. The generation owner reuses its existing writer ownership when optionally capturing the extra proof; a failed optional capture does not block existing generation promotion and clears any stale tuple. It does not claim an atomic snapshot against out-of-band operators that bypass existing owner barriers; any observed instability fails closed.

Named counter objects are validated for owned family/table, unique nonempty name and valid counter values; declarations contribute to the semantic hash while packet/byte values do not. Missing owner receipts still stop the collector; parser compatibility creates no receipt or new state owner.

## Explicit Core IP receipt re-attestation

`fwrouter core ip-receipt-reattest --plan` and the plan-bound `--apply` mode are a separate root-only Core owner operation for a retained strict proof-only generation checkpoint. The plan pins both (1) the exact executing source-tool backend manifest and (2) the exact existing installed backend manifest at the fixed `/opt/fwrouter-api` path. These are distinct identities: running the reviewed source tool does not install it, change the backend selector, or claim that the stopped/running API is executing that tool. The command's ordinary shared maintenance lease is acquired by this CLI process; it does not assert that another API process owns that lease.

The operation accepts only a complete `proof_only_legacy_admission` checkpoint in `proof_complete` phase with `require_native_proof=true`. It binds the plan to that checkpoint's exact bytes, operation ID, source fingerprint, verified inventory/revision, selection revision, Core intent/latest apply, complete database snapshot digest and Core owner artifacts. Existing `_core_readback` checks remain strict except for one explicit internal path that permits the exact currently hashed Core receipt to have an outdated IP semantic digest. `_core_ip_facts()` must still pass all required policy checks; nft, Core intent, apply, artifacts, runtime context and closing stability remain fully checked. The default `_core_readback` and all normal native proof callers still reject an IP receipt mismatch.

Apply requires the exact fresh plan digest and literal `CORE_IP_RECEIPT_REATTEST` confirmation. Under the existing shared maintenance admission and exclusive `xray_writer_guard`, it repeats the full plan read, writes only `native_ip_semantics_sha256` in the existing Core owner receipt using the existing atomic JSON publication primitive, then re-reads the strict Core owner state and exact checkpoint/database/source fences. It never changes SQLite, generation markers/checkpoints, selectors, Core intent, nftables, routes, services or backend files. A post-publication mismatch returns `INCOMPLETE` and preserves evidence; it does not roll the receipt back or fabricate success. Once the corrected receipt is present, the existing installed-backend strict generation owner command may be retried against the same checkpoint.

The CLI's narrowly scoped shared lease validates a complete ordinary schema-2 checkpoint against the separately pinned installed OLD manifest, while checking the executing source tool against its own exact manifest pin. It does not call or weaken general startup admission. It may create the existing root-owned controlled-rollout directory/lease file if absent; the writer guard may create its existing run directory/lock file. Nested application database projections execute under `readonly_db_session_scope`; only the existing Core receipt publication is writable. Apply additionally atomically replaces the one Core receipt and may leave the atomic writer's bounded temporary file if the filesystem fails before rename. No broader lifecycle checkpoint or selector publication is performed.
