# `fwrouter_api.services.native_proof`

## Purpose

`collect_native_proof(scope="ui", expected_backend_manifest_sha256=..., expected_xray_image_digest=..., expected_mihomo_image_digest=...)` produces a bounded, read-only proof for the managed Xray, Mihomo, and Core state consumed by the UI. Its source identity is the exact installed backend content manifest rooted at the resolved `__file__` of the executing module; `FWROUTER_BACKEND_ROOT` cannot redirect attestation, and the module does not infer a Git commit from installed files. Runtime pins are the immutable local Docker image configuration IDs (`docker inspect .Image`), not registry manifest digests (`RepoDigest`); missing pins return `INCOMPLETE`, and observed IDs must match. Configured image references and reported runtime versions are checked separately.

## Read and consistency contract

- Requires an exact expected backend manifest SHA-256 and reports `STALE` when installed content differs.
- Opens SQLite with `mode=ro`, `query_only=ON`, and explicit read transactions. It captures schema/integrity/foreign-key state, generation and monotonic selection/Core revisions, latest apply ownership, active jobs, and the generation checkpoint before and after native readbacks.
- Holds `xray_writer_read_guard()` across the proof. The guard takes a nonblocking shared flock on the existing Xray writer lock only; it never creates or changes a lock file. Missing lock or active writer yields `INCOMPLETE`.
- Reads active/mounted Xray configuration and HandlerService users, and compares loaded identities plus durable binding/mode projections against the active config. Mihomo compares the complete generated semantic config, actual native top-level rules and owned selector memberships, and the effective native target against the durable Core selection in auto/fixed mode. Core compares the applied manifest, owner-recorded canonical live nft table semantics (all owned chains/rules/sets/named counter declarations; only volatile counter values, handles, and elements in the two named runtime DNS timeout sets are normalized), required chains/mode, and a SHA-256 over the complete ordered IPv4/IPv6 `ip rule` state plus the complete table-100 route state. It requests numeric table output from `iproute2` (`-N`) so local `/etc/iproute2/rt_tables` aliases cannot change policy comparisons. Local default-route readback accepts the documented `local` name or numeric `RTN_LOCAL` value `2`; unicast (`1`) never satisfies the check. The Core apply receipt binds that same routing-state hash; added/removed/reordered rules or route changes therefore fail parity instead of passing a marker-only check. Raw IP rows stay in process memory and are not persisted or returned; the receipt and public proof contain only their digest. It then rechecks relevant runtime incarnations and configuration identities.
- The Core manifest comparison intentionally excludes `active_auto_server_id`: the selection owner may update it without a Core manifest republish. Its revision is fenced, and Mihomo's actual selector target is separately resolved against the durable logical server ID.
- Generation proof digest and revision must exactly match the verified inventory. The generation owner may persist an additional native-proof tuple only after successful capture; legacy markers without that tuple remain readable but produce `INCOMPLETE` until a normal qualified owner promotion captures one.
- Returns only structured status and redacted identities. Raw configurations, credentials, UUIDs, selector names, job IDs, and durable source fingerprints are never included.
- `PASS` requires supported scope, exact source identity and runtime image pins, stable fences, healthy database integrity, no active jobs, a verified subscription generation and matching owner receipt, and successful native readbacks. Runtime unavailability or missing owner evidence is `INCOMPLETE`; contradictory readback is `FAIL`; changed fences are `STALE`. Public results expose only redacted hashes/counts, a proof schema version, executed-check names, and stable reason codes; unknown exception text is not returned.

## Operational boundary

This collector is observation only. It does not enter admission/staging/reconcile/apply paths, write probe caches, create temporary configs or Docker state directories, or alter SQLite/checkpoints/configs. Nested application projections run under the context-local `readonly_db_session_scope`; attempted writes fail through SQLite `query_only` and do not fall back to writable sessions. In WAL mode SQLite may update shared-memory reader bookkeeping, so the contract protects durable database/config state rather than promising bit-for-bit unchanged WAL/SHM files. The generation owner reuses its existing writer ownership when optionally capturing the extra proof; a failed optional capture does not block existing generation promotion and clears any stale tuple. It does not claim an atomic snapshot against out-of-band operators that bypass existing owner barriers; any observed instability fails closed.

Named counter objects are validated for owned family/table, unique nonempty name and valid counter values; declarations contribute to the semantic hash while packet/byte values do not. Missing owner receipts still stop the collector; parser compatibility creates no receipt or new state owner.
