# `installer/ui_publication.py`

Publishes the FWRouter UI into immutable content-addressed release directories and atomically switches `/opt/fwrouter-ui` with Linux `renameat2(RENAME_EXCHANGE)`. It verifies the installed backend against the trusted source backend using the canonical filtered manifest in `controlled_backend_lifecycle.py`, serializes publishers with an invoking-identity-owned mode-`0600` lock, validates path ancestry, ownership, web-server-readable modes, symlink-free content and bounded size/count, fsyncs candidate data and both sides of archival renames, and retains the complete previous tree on interruption or postflight failure. Initial UI directories are content-addressed after exchange; a later publisher recovers a complete old tree left at the exchange path. The explicit `--restore-release SHA256` path reuses this publisher only when the trusted source UI digest matches the retained release and the backend manifest matches installed state; it does not restore the backend or perform automatic rollback. Live publication requires root-owned source/installed trees; `--target` uses disposable invoking-user-owned paths. Normal UI installation is called by `installer/install.sh`; the same helper CLI exposes the constrained explicit restore operation.
