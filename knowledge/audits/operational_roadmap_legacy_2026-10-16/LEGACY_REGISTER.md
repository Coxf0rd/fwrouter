## Risks and evidence required before later removal

Any future pruning of migration steps or legacy data transforms must first declare the oldest supported schema and inventory supported inputs; then demonstrate data/identity/credential/fence preservation, sequential upgrades from each supported predecessor, idempotent restart, failure/retry behavior, future/unversioned/corrupt DB rejection, canonical structure/integrity checks, and backup restore/rollback behavior in isolated fixtures. Include startup and installer upgrade semantics so DB state is not confused with copied source. Destructive interruption/crash acceptance is a separately authorized staging gate; no such tests were run here.

A proposed reduction of connection setup belongs to measured owner-scoped execution work: split permission-only from transaction sharing, compare same and changed rows with equal durability, test concurrent create/sidecar repair and rollback/event atomicity, and retain the existing owner/fence contracts. The deep report does not approve implementation.
